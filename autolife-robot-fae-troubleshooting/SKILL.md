# Autolife 机器人 FAE 现场故障排查

> 完整描述：Use when 排查 Autolife/智动未来机器人现场故障（不抓取、电量异常、导航偏差、识别失败、服务离线）. 检索内部知识库后输出分型排查方案.

## 触发
用户（FAE）问 Autolife/智动未来 S1/S2/太空舱机器人现场故障：不抓取、抓空/抓偏、电量显示异常、导航偏差、识别失败、服务不在线等。

## 流程（按序执行）

1. **先检索内部知识库，不凭空编命令**。根目录 `/home/kk/.hermes/knowledge/`；按 `references/kb-map.md` 定位文档。中文关键词用 `|` 交替组带 `file_glob: *.md` 搜，命中后 read_file 分页读上下文；第一轮结果太散（`total_count_is_lower_bound`）就换更具体的词或限定 path 到 `reviews/`，不全文读大文件。
2. **分型优先**：同一现象（不抓、恒 100% 电量）会在链路不同环节产生。先给"现象 → 卡点 → 归因模块"分型表，再按分型给步骤——不分型直接给单线步骤会掩盖真实卡点。
3. **每个分型按"验证手段（只读优先）→ 修复动作（带命令）→ 复测"组织**；命令/参数/路径必须来自知识库文档，文档没有的不编造，宁可说"查 XX 日志"。
4. **收尾单独列安全红线**：禁止盲重试、禁止绕过安全确认门、改配置先备份、异常保留当轮日志再排查。

## 常任规则

- **归因边界**（场景流程文档规定）：小车到位/导航偏差归 **GV/SLAM**；识别与抓取异常归 **AI/dataset**；屏幕点击、落盖、二次抓取归 **AI 与商品 JSON**。定位或路点偏差过大时继续调末端抓取参数会掩盖根因——先归位再调参。
- **改配置三纪律**：先备份；只替换指定字段、保持 YAML/TOML/JSON 原格式；改完重启对应服务并复测——**XML 改动须重启 flow，dataset 热生效；改了不重启等于没改**。
- **硬件检测前置**：电池/雷达等检测要独占总线——检测前停对应服务（服务的 ROS 节点同时在订阅会抢数据导致检测不到或误判），测完恢复。
- **偶发故障不重启"洗白"**：保留当轮日志/网络/温度，开返工单；不连续盲重试。
- 精读笔记中标"待验证/建议"的条目，转述时保留限定语，不把建议写成已验证事实。
