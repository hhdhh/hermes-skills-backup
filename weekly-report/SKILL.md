# weekly-report — 周报四段草稿

> 完整描述："Use when 用户发周报四段模板（本周总结/复盘与判断/需要的支持/下周规划）或一句话周总结要成稿。四段固定格式、短句、无 emoji、可直接粘贴。"

## 触发

- 用户贴出四段模板（本周总结 / 复盘与判断 / 需要的支持 / 下周规划）
- 用户给一句话本周工作描述（如"这周负责遥操数据清洗、装机和测试"）要周报
- 用户说"回复一下"——按原格式重发，不大改

## 输入处理规则

- 一句话输入**直接起草**，不反问、不列清单要材料——用户靠迭代改稿，不靠补信息
- 模板要求"根据飞书内容回答"但没附链接 → 按用户已给的工作描述起草，末尾注一句：需引用飞书数据请给链接
- 多项工作（装机 + 测试 + 学习 X）全部织入"本周总结"，学习类条目在"下周规划"回声一次
- 不编造数字和成果；用户没给量化就写定性结果

## 输出格式（固定）

四段、粗体标题、顺序不变：

**本周总结** —— 亲自完成了什么 + 结果。动词开头（完成/参与/推进），区分"负责/参与/对接"层级，不夸大。
**复盘与判断** —— 一条有效判断 + 一条待调整项，都扣本周实际工作；判断写成"X 做法有效，因为 Y"，调整项写成可执行的沉淀动作（固化清单/明确标准）。
**需要的支持** —— 验收标准或口径确认 + 跨部门问题闭环，用"希望/需要"句式，不指责。
**下周规划** —— 延续现有线索 + 问题闭环 + 一个能力提升主题，与本周工作衔接。

## 风格（每次都生效）

- 每段 1-3 句，短句，零 emoji，零客套，零结尾提问
- 正文与聊天都不用"主人"等称呼
- 直接输出可粘贴文本，外面不包大段解释

## 迭代指令的固定响应

- "再换个说法" → 保持篇幅，换组织方式（并列式 ↔ 叙述式），不增删信息
- "再简短一点" → 压到每段 1 句，砍修饰语，保四段骨架
- "回复一下" → 原格式重发，内容微调
- 任何迭代都不加回已砍掉的内容
