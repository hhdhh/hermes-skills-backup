## I — 自述

S2 装机是从裸机到可交付的三段流程：S0 基线冻结（G0 门：机型/版本/磁盘/网卡/路径/备份/急停/测试区确认——此阶段只允许只读检查）→ S1 系统初始化（G1 装配签名 + G2 配置验证：语法/身份/MAC 映射/Netplan try/路由/DNS/设备节点）→ S2 业务部署。

最高危动作是配置：**绝对不能用 .example/.default 模板直接覆盖生产配置**——模板不含机器特有参数（编号/网卡/USB 地址/License/标定），覆盖=身份丢失+硬件失配。正确路径是字段级三方合并（厂商默认+机型基线+机器实例配置），改后语法+硬件+服务+业务四重复验。

每步都有失败动作：G0 不过不动工；G1 不过退回装配工序重测受影响项；G2 不过回滚本次配置。Web 前端装机向导默认 0.0.0.0 监听（现场任何人都可操控），测试完必须关。

## A1 — 书中案例

**案例类型：反例警示**（模板覆盖事故，来源：装机规范反模式）

- 输入/问题：新机初始化图快，用 .example 配置直接覆盖
- 方法执行（错误示范）：cp example config.yaml → 服务起来但身份错乱（编号是模板默认值）、USB 映射失配、License 不识别
- 结论：退回 G2 重做初始化；正确做法=测试前快照恢复或字段级合并

**案例类型：书中亲历案例**（Netplan try 的价值）

- 网络配置写完直接 restart networking → 断联 → 只能现场接显示器救；用 netplan try → 120s 无确认自动回滚，保住连接

## A2 — 未来触发 ★

**情境：**

1. 新 S2 机器人从裸机装机到交付
2. 机器人重装系统后恢复配置
3. 换网卡/主板后重新初始化
4. 装机过程中网络配置差点断联
5. 批量装机时的配置一致性

**语言信号：**

- "新机装机" / "裸机装" / "初始化" / "重装"
- "S0 S1 S2" / "基线冻结" / "G0 G1 G2"
- "netplan" / "MAC 映射" / "udev"

**区分：**

## E — 可执行步骤

**输入契约**：机号+机型（必填）；装机清单版本（必填，来自发布矩阵）；是否重装（必填——决定有无旧配置可参考）。

**Step 1 S0 基线冻结（G0）**：逐项确认机型/版本/磁盘/网卡/路径/备份/急停/测试区——**只读检查**，任何不过不动工
**Step 2 S1 装配与初始化**：
1. G1 装配质量：机械/电气/零位/急停/充电/散热/接口逐项签名，返工项重测
2. G2 系统初始化：配置语法校验→身份（ROBOT_ID/hostname）→MAC 映射→`netplan try`（勿直接 restart）→路由/DNS→设备节点（udev）
**Step 3 配置合并（高危红线）**：**禁止模板覆盖**。字段级三方合并：厂商默认+机型基线+机器实例；合并后 md5 备份三份
**Step 4 S2 业务部署**：按机型 ENABLED_MODULES 部署服务 → 四重复验（语法+硬件枚举+服务状态+业务探活）
**Step 5 收尾**：关装机 Web 前端（0.0.0.0 暴露）→ 初始化记录归档（含变更清单+配置差异+签名）
**判停点**：G0 任一项无法确认 → 停止装机（无法建立基线）；G2 netplan try 失败 → 用其自动回滚，人工排查后再试；发现自己在"复制粘贴旧机器配置" → 停，转 Step 3 合并流程

**输出契约**：初始化记录（只读预检摘要+备份位置与校验+变更清单+配置差异+驱动枚举+服务状态+ROS 探活+网络可达+签名）——外发版本必须脱敏。

## B — 边界

- **不适用**：装机完成后的验收放行（autolife-ops-shipment-acceptance）；装机中的故障诊断（autolife-ops-robot-diagnosis）；S1 老机型装机（路径/服务不同）
- **反场景**：跳过 G0"边装边确认"；为省事跳过 netplan try；装机 Web 前端开着过夜
- **失败模式**：模板覆盖丢身份；写死 IP/设备号/路径；只看服务 active 不做业务探活；人工验收空表当完成记录
- **相邻易混**：本卡的 G0-G2 是装机门，shipment 卡的 G4-G6 是验收门，一条链上的两段
