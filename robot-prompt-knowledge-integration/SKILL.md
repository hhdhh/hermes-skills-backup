# Robot Prompt · 知识库增量集成

> 完整描述：把外部知识库（如飞书 docx 销售百问 / FAQ / 产品手册）增量集成进已有机器人/角色 prompt。当主人说"把 X 加到机器人 prompt"、"机器人回答 Y 问题"、"用飞书文档喂机器人"时触发。覆盖身份冲突检测、关键词触发式挂载、结构化 QA 抽取、prompt 体积护栏。

## 何时用

主人在已有的"机器人/角色 prompt"上，要接入一份**外部知识库**（飞书 docx / Notion / PDF / 表格 FAQ），让机器人能回答该领域的具体问题。

## 核心原则（主人授权的接法）

**任何时候都优先：触发式挂载，不污染主身份。**
理由：机器人 prompt 里的"角色设定 / 语气 / 长度限制"是上层契约。把不相关的行业知识全文塞进去，会让机器人在错的话题里强行答，破坏人设、突破长度限制、烧 token。

只有以下三种情况例外：
- 主人明确说"全文塞进去"
- 文档就是机器人的本职知识库（如产品手册 → 产品机器人）
- 主身份本身就是要覆盖该领域（如销售机器人 → 销售百问）

---

## 标准 6 步工作流

### 1. 身份冲突检测（**必做，先停下**）

接到任务，**先读两份东西**：
- 原始 prompt（机器人身份 / 公司 / 产品 / 语气 / 长度限制）
- 外部知识库的实际内容

判断：
- 文档业务域 vs 机器人身份业务域 → 一致 / 弱相关 / **冲突**
- **冲突 = 必须停下来问主人 3 选 1**（见下"冲突三问"）

不要把"主人说加就加"当成默认执行——身份冲突会让机器人变成胡说八道的工具。

### 2. 冲突三问（停手问主人）

发现冲突时，**只问这 3 个选项，不要列更多**：

1. **文档错了** —— 主人发错链接，能给正确链接
2. **应用场景改了** —— 机器人真的要做该领域工作（不只是回答几个问题，是主营业务变了 → 整份 prompt 要重写）
3. **触发式子模块** —— 机器人偶尔会被问到，不影响主身份，只在关键词命中时引用

主人选 3 = 走"触发式挂载"流程（见 step 4-6）。
主人选 2 = 走"重写 prompt"流程（**不是本 skill 范围**，回退到主人明确指令）。
主人选 1 = 让主人重发链接，**立刻停下**。

### 3. 内容结构化抽取

外部知识库如果是结构化 QA（飞书销售百问 / FAQ / 培训手册）：

用 markdown 的 `### 问题标题` + 下一段 `答：xxx` 模式正则抽取：

```python
import re
pattern_q = re.compile(r'^### (.+?)$', re.MULTILINE)
questions = pattern_q.findall(md_text)

def extract_after_answer(text, q_title):
    idx = text.find(f'### {q_title}')
    if idx == -1: return None
    after = text[idx:]
    m = re.search(r'答[:：]\s*(.+?)(?=\n### |\n## |\Z)', after, re.DOTALL)
    return m.group(1).strip() if m else None
```

统计：总标题数 / 有效问答对（**期望 100% 命中率**）。
抽样验证：开头 / 中段 / 末尾各 3-5 个，确保抽取没断。

输出到本地 `.md` 文件保存原文 + 一份结构化 QA 索引（`[问题] → [答案前 80 字]`），给下一步触发匹配用。

### 4. 触发式挂载设计（**默认推荐**）

如果主人选 3，按这套模板扩展原 prompt 末尾：

```markdown
# 专项知识 · [领域名]（仅关键词触发）

## 触发规则
- 关键词命中：[关键词 1] / [关键词 2] / [关键词 3] / ...
- 命中时：按下方"知识索引"定位答案，简短回答（≤原 prompt 长度限制）
- 未命中：保持原主身份回答

## 知识索引（[N] 条）
- 主题 1 → 见 `~/.hermes/knowledge/[file].md#L[start]`
- 主题 2 → 见 `~/.hermes/knowledge/[file].md#L[start]`
- ...

## 身份原则
你是 [机器人身份]，不是 [领域] 从业者。
被问到该领域时用以上知识辅助回答；不主动展开、不强推。

## 长度限制
[沿用原 prompt 限制]，长答案按要点压缩，禁止输出 Markdown。
```

关键词清单构造：
- 文档里出现的高频实体名（项目名 / 产品名 / 地块编号 / 合作单位）
- 数字编号（地块编号 / 户型编号）
- 公司名 / 品牌名

### 5. 体积护栏（**必做**）

- ✅ prompt 增量 < 1KB（仅关键词表 + 触发规则）
- ✅ 全文保存在外部 `.md`（如 `~/.hermes/knowledge/<topic>_qa.md`）
- ✅ 关键词命中后引用即可，**不要在 prompt 里写全文**
- ❌ 全文塞 prompt = 单次对话浪费几万 token + 长度限制失效

### 6. 给主人看最终结果

- 输出完整 prompt（diff 风格：原 prompt + 新增"专项知识"块）
- 至少 3 个触发示例（命中 / 不命中 / 命中但问得太细）
- 标注"如何回退"：删掉末尾的"专项知识"块即恢复原 prompt

## 坑（pitfalls）

**1. 飞书 docx 公开 URL 抓回来是登录墙**
- 机制：飞书 docx URL 需要登录态，公开 GET 只返回登录页 HTML
- 解法：用 `lark-cli docs +fetch --doc <url> --as user`，**子命令前面带 `+`**

**2. lark-cli 子命令是 `+fetch` 不是 `fetch`**
- 机制：lark-cli 1.0.x 用 `+` 前缀标记动作（fetch / update / delete 都是 `+` 开头）
- 解法：所有写操作 `+update` / 读操作 `+fetch`，先 `lark-cli <group> --help` 看子命令列表

**3. JSON 解码中文 markdown 不要用 `unicode_escape`**
- 机制：lark 返回的 JSON 字符串里，`\n` 是真换行的 JSON 转义，但中文字符不需要再 escape。`codecs.decode(..., 'unicode_escape')` 会把中文当成 `\u` 转义序列处理，结果全变乱码
- 解法：用 `json.loads(完整_json)` 一次性解，中文自然保留

**4. 主人说"加进去" ≠ "全文塞进去"**
- 机制：主人语义是"让机器人能回答"，不是"让 prompt 物理上包含全文"
- 解法：默认走触发式挂载；只有主人明确说"全文 / 完整加载 / 全量"才走全文方案

**5. 抽取问答对前先抽样验证**
- 机制：飞书 docx 转 markdown 后，正文里可能混着表格、列表、附录，单纯正则可能抽到非 QA 段落
- 解法：抽完后跑 `valid_pairs / total_questions`，期望 100%；不达 100% 要回头看哪些标题没匹配（可能是空标题 / 多级标题 / 子标题被算进去了）

**6. 关键词表一定要含"业务别名"**
- 机制：访客不会用文档原标题问，会用口语 / 别名（如"那个海景房""特发的项目""03-01-1 地块"）
- 解法：关键词表 = 文档高频实体 + 口语化别名 + 编号（地块/户型/楼栋号），三类都要

**7. prompt 改动前先备份原版**
- 机制：机器人 prompt 一旦改坏，回滚成本高（要重抓文档、重抽 QA）
- 解法：把原 prompt 写到 `~/.hermes/prompts/<robot_name>.bak.md`，再加新内容；改坏一行 cp 回来

## 输出模板（生成给主人看的格式）

```markdown
## ✅ 知识集成完成

**集成方式**：触发式子模块（关键词命中）

**Prompt 改动**：
- 新增尾部"专项知识 · 小梅沙（仅关键词触发）"块（+XXX 字节）
- 原 prompt 全部保留

**关键词表**（N 个）：小梅沙 / 特发 / 03-01-1 / 容积率 / 美高梅 / ...

**知识索引**（265 条）：见 `~/.hermes/knowledge/xiaomeisha_qa.md`

**触发示例**：
1. 访客："小梅沙有什么户型？" → 命中 → 答户型配比
2. 访客："这里有什么餐厅？" → 不命中 → 走原前台回答
3. 访客："03-01-2 容积率多少？" → 命中 → 答容积率

**回退**：删 prompt 末尾"# 专项知识"块即可恢复原版
```
