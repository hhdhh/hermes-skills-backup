# 案例：192.168.10.2 ping/ssh 全超时（2026-08-07）

> 主人 ping 192.168.10.2 → 全 timeout；ssh 22 → timeout；nc 8 个端口全 timeout；
> 但 arp 能拿到 MAC `c8:98:db:40:6e:f5`。
> 结论：**目标设备很可能已离线**，但交换机保留旧 ARP 缓存。
> 同时主人**复制带 `#` 注释的命令到 zsh 报 `command not found: #`**。

## 主人环境

- MacBook Air M5（2025 款，Apple Silicon）
- macOS 27.0
- en0 (Wi-Fi): `192.168.65.34/24` 默认网关 `192.168.64.1`
- en5（USB 网卡 / 桥接）: 走 `192.168.10.2` 的流量出口
- 主人 ABSOLUTE 模式

## 完整执行命令链

### 第 1 步：定位 Mac 自己

```bash
ipconfig getifaddr en0
# 192.168.65.34

route -n get default | grep gateway
# gateway: 192.168.64.1
```

**判断**：Mac 在 `192.168.65.0/24` 网段，目标在 `192.168.10.0/24` 网段，**不同网段**。

### 第 2 步：定位流量出口

```bash
route -n get 192.168.10.2
#   route to: 192.168.10.2
# destination: 192.168.10.2
#   interface: en5
```

**判断**：流量走 `en5`（不是 en0）。Mac 当前有第二个接口，可能是 USB 网卡 / 雷雳桥接 / 虚拟网卡（Docker/OrbStack/Parallels 都有可能）。

### 第 3 步：ARP 二层检测

```bash
arp -n 192.168.10.2
# ? (192.168.10.2) at c8:98:db:40:6e:f5 on en5 ifscope [ethernet]
```

**判断**：ARP 有 MAC，`en5 ifscope` 表示走 en5 二层。

⚠️ **但这不代表设备真的活着**——交换机/路由器会保留 ARP 缓存几分钟到几小时。

### 第 4 步：TCP 端口扫描

```bash
for p in 22 80 443 2222 3389 5900 8080 8443; do
  nc -vz -G 2 192.168.10.2 "$p"
done
# 8 个端口全 Operation timed out
```

**判断**：目标设备没有响应任何 TCP 连接。可能是：
1. 设备已关机/死机
2. 设备防火墙丢弃所有入站
3. AP 隔离 / VLAN 隔离
4. `192.168.10.2` 是旧地址

### 第 5 步（建议补做但本轮没跑）

```bash
# 清 ARP 缓存
sudo arp -d 192.168.10.2

# 重新 ping 触发 ARP 学习
ping -c 3 -W 1000 192.168.10.2

# 持续 5 次看 MAC 是否稳定
for i in {1..5}; do
  date
  arp -n 192.168.10.2
  sleep 2
done

# traceroute 看断在哪一跳
traceroute -m 5 192.168.10.2
```

## zsh 注释陷阱

主人**直接把带 `#` 注释的命令块复制到 zsh**，每行 `# xxx` 报：

```
zsh: command not found: #
```

**两种修复**：

1. **临时一次性**：

```bash
setopt interactivecomments
```

2. **永久**：在 `~/.zshrc` 加：

```bash
setopt interactivecomments
```

3. **下次给主人命令时只发命令本身，不发注释**（推荐）。

## 主人接下来要做什么

1. **去目标设备本地**（物理接触），确认它真的开机 + 网线/Wi-Fi 插好
2. **确认目标设备 IP 真的是 192.168.10.2**（不是旧的、不是 DHCP 换的）
3. **如果目标是 Windows**：
   - 检查 `Get-Service sshd` 状态
   - 防火墙入站规则允许 22 端口
   - 启用网络发现（"专用网络" profile）
4. **如果目标是 Linux / 开发板**：
   - `systemctl status ssh`
   - `ss -lntp | grep :22`
   - `nft list ruleset` 看防火墙

## 这次没跑但应该跑的（备用诊断）

```bash
# 看 Mac 上所有接口
networksetup -listallhardwareports
ifconfig | grep -E "^[a-z]|inet " | head -20

# 看 en5 是不是 USB 网卡 / 虚拟网卡
system_profiler SPUSBDataType 2>/dev/null | grep -A 2 "Ethernet" | head -10
system_profiler SPThunderboltDataType 2>/dev/null | head -20

# 扫整个网段，看哪些 IP 真的在
nmap -sn 192.168.10.0/24
# brew install nmap 后可用
```

## 学到的关键模式

1. **Mac 多接口时代**：M5 Mac 经常有 en0 (Wi-Fi) + en5 (USB 网卡 / 雷雳) + en1 (雷雳桥) + 虚拟接口 (Docker/OrbStack)
2. **目标在不同网段不稀奇**：Mac Wi-Fi 上网 + USB 网卡连工控网/机器人网很常见
3. **ARP 有 MAC ≠ 设备在线**：交换机保留旧缓存
4. **TCP 全 timeout 时优先排除"目标真离线"**：别死磕 SSH 客户端，去目标本地看
