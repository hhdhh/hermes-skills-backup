**实际功能分类**：

- `acp_adapter/`（11 个）—— **Agent Communication Protocol 子包**，让 hermes 可作为 ACP server 跑（entry point `bin/hermes-acp`）
- `credential_lifecycle.py` —— **统一 provider credential 三方存储一致性**（`.env` / `auth.json` credential_pool / `config.yaml` mirror）choke point。修 issue #51071/#59761/#62269
- `input_sanitize.py` —— **清掉 terminal bracketed-paste control sequence leak**（修 issue #62557 desktop `~[[e` corruption signature）
- `urllib_security.py` —— **出站 HTTP 安全加固**（`SafeCredentialRedirectHandler`：redirect 只在同 origin 时保留 header）
- `cli_billing_mixin.py` —— CLI billing/计费 mixin

### 删除 4 个包/模块

```
- hermes_cli/dashboard_auth/        (旧 dashboard 鉴权 → web UI 接管)
- hermes_cli/memory_providers.py     (旧 memory provider)
- hermes_cli/proxy/                  (旧 proxy 客户端)
- hermes_cli/subcommands/            (旧子命令框架)
```

### 148 个文件的 content diff（量大未逐行审）

常见内容变化点（从启动 log 反推）：
- **Secrets 处理加固**：0.18.2 已有 `Secret redaction`，0.19.0 走 `credential_lifecycle.py` choke point
- **Output 文本消毒**：0.19.0 加 `input_sanitize.py` 处理 desktop paste 异常
- **Cross-origin 头策略**：0.19.0 加 `urllib_security.py` 限制跨 origin header 转发

## 关键 pitfall（写在 SKILL.md 陷阱 5）

**不要凭启动 log 字眼判 NEW feature**：

- 看到 0.19.0 启动时打 `Secret redaction: ENABLED` / `kanban dispatcher: another gateway already holds the dispatcher lock` 就跟主人说"这是 0.19.0 NEW"
- **错的**：tar 备份里 0.18.2 的 hermes_cli/config.py 就已经有 "Secret redaction" 字符串
- **正解**：用 file-level diff —— 0.19.0 真的 NEW 增量是 15 个 .py 文件，不要被启动 log 字眼带走
