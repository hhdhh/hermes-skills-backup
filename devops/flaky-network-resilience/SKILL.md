# 间歇性网络劣化：诊断与韧性加固

适用：跑在 WiFi 工作站/现场机上、依赖外部 API（ASR/LLM/TTS/云服务）的服务，整体能通但阵发卡慢（几十秒延迟）或部分环节无声。与 `network-connectivity-diagnosis`（完全连不上）互补：那边查断点，这边查劣化层。

## 诊断流程（按序，先定位层再动手）

1. **分段耗时定位共享依赖**：看服务日志里各环节耗时（如 ASR/LLM/TTS 各自有打点）。基线心里要有数（如 ASR~1s/LLM~3s/TTS~2s）。**多段同时慢 = 共享依赖坏了（出网/DNS），单段慢才是该 API 自己的事**。不要见慢就换 API 提供商。
2. **分层 ping 分离责任**：ping 本地网关 → WiFi 层；ping 公网目标 → 出口层；ping 内网对端（如 mesh 机器人，常 0.x ms）→ 排除 mesh/内网嫌疑。网关烂=本机 WiFi；网关好但公网烂=运营商/公司出口拥塞（软件只能扛不能修）。
3. **WiFi 间歇抖动（延迟几十 ms~3s 跳变、阵发丢包、时好时坏）首查网卡省电模式**：Intel 卡阵发微睡眠是头号嫌疑。`nmcli -g 802-11-wireless.powersave con show <SSID>` 值为 default 即嫌疑 → `nmcli con modify <SSID> 802-11-wireless.powersave 2 && nmcli dev reapply <dev>`，关后复测本地网关延迟（正常应 <10ms 零丢包）。
4. **DNS 阵发失败**：公网 DNS（UDP 53）随拥塞丢包 → 域名解析超时把所有 API 拖到几十秒。特征：同一 API 时而 0.8s 成功时而 20s+ 超时；`Temporary failure in name resolution`。诊断：`nslookup <域名> 223.5.5.5` vs `119.29.29.29` 交替测。修法见加固模式 A。
5. **单一端点被网络设备掐**（如某域名 SSL reset、其它域全好）：公司网/酒店网会针对性 reset 特定境外端点。诊断：单独 curl 该域名连通性。修法：同通道备选提供商自动切换（模式 B）。
6. **副接口陷阱**：多网卡机器上插着网线不代表能出网——绑接口 ping 公网实测（`ping -I <iface>`）分清内网专用口与真出网口，别盲目切默认路由。

## 加固模式（按需织入服务代码）

- **模式 A · DNS 缓存补丁**：monkey-patch `socket.getaddrinfo`，成功结果缓存 600s，解析失败时回退过期缓存。对所有 urllib/SDK 域名调用一次性生效。代码见 references/resilience-patterns.md。
- **模式 B · 提供商主备自动切换**：主 TTS/ASR 失败或返回空时自动落同通道备用（如 edge-tts→dashscope 系 TTS，备用与另一存活 API 同通道意味着同生共死概率低）。切换要记日志且不重试主提供商死循环。
- **模式 C · 每请求超时 + 安抚语**：外部调用设 25s 级超时，超时丢弃该话轮并给用户一句「刚才没听清，您再说一遍？」——坏窗口只丢一拍，不卡死整条链。
- **模式 D · 即时应答盖住思考期**：任何 >1s 的处理管道（唤醒→LLM）前先立刻回一句预合成的短应答（缓存预热，零合成延迟），否则静默期体感=没反应。预热必须 `asyncio.create_task()` 挂在端口监听之后——直接 await 会推迟端口/控制 socket 出现。
- **模式 E · 按句流式输出**：长回复整段合成完才播是反模式（20s+ 全静默）；按句切分、首句 ~2s 开播、边播边合成后续。短句（<12字）并入前句防碎片化。
- **流式发送节奏**：音频片下发间隔按「每片音频时长 ÷ 3.3」设（如 200ms 片 → 60ms 间隔），留 3x 实时余量吸收无线抖动。

## 回归纪律

- 改 VAD/门控/流式后必跑注入回归（合成语音喂服务完整走 ASR→agent→TTS），量「首包音频延迟」和完整 transcript——某次调参把真实话音全部拦掉的事故只有回归能抓住。
- 注入测试器收到第一段就断线属工具局限，主回复仍在服务端跑完——看服务日志判链路健康度，别误判为服务故障。
- 观测 ping 用短窗口多次（`-c 8 -i 1`）：长窗口单次会被阵发坏窗污染或工具自身超时误导。

## 陷阱
- 症状「AI 对话有问题」九成是网络层：先分段计时，别先怀疑对话逻辑/配置/密钥。
- 内存 swap 满不一定是慢因——网络调用慢时先测延迟分层，排除后再查资源。
- 关省电只对当前连接生效，换 SSID/重装系统后要重查。
