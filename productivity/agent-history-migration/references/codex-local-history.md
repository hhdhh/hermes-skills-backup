# Codex local history import

## Discover the installed protocol

Run `codex --version`, `codex app-server --help`, and `codex app-server generate-json-schema --out <temporary-directory>`. Inspect request properties and the protocol method enumeration: a schema type name does not specify wire spelling. In the tested protocol, the endpoint is `thread/inject_items`, not `thread/injectItems`.

Use `codex app-server --stdio` as a local JSON-RPC subprocess. Initialize with a client name/version and `capabilities.experimentalApi: true`, then send `initialized`. Match response IDs and handle interleaved notifications. Do not call `turn/start`. Disable configured hooks, memory generation, and unnecessary MCP startup for the migration process only, using options supported by the installed release.

## Validate storage versus UI separately

A successful raw-item injection can append Responses items without creating UI turns. Check `thread/read` with `includeTurns: true` and, for paginated histories, `thread/turns/list` and `thread/items/list`. Ephemeral threads may reject full-turn reads, so they are useful format probes but not persistence acceptance tests.

If native import support cannot represent visible historical turns, the tested alternative is legacy rollout construction followed by a fresh local API reader. Check that the current release still supports it before bulk publication. Do not edit a live loaded thread or application database directly.

## Construct a legacy rollout

1. Obtain `session_meta` structure from a harmless thread generated by the installed binary; inspect only metadata, not unrelated private conversation text. Allocate a unique UUID and safe new destination path under the active `CODEX_HOME/sessions/YYYY/MM/DD/` tree.
2. Set source identity, ID/session ID, original timestamp, intended local workspace, and current target provider. Do not transplant source agent instructions as authoritative system instructions. For a legacy file, omit paginated-only `history_mode` and `context_window` metadata; falsely labeling a hand-built rollout paginated can hide its items from the reader.
3. Serialize JSONL records with `timestamp`, `type`, and `payload`. Start with `session_meta`, then an `event_msg` of payload type `task_started` with a unique turn ID.
4. For each historical message emit both representations:
   - `response_item`: `{type: message, role: user|assistant, content: [...]}` using `input_text` for user text and `output_text` for assistant text.
   - `event_msg`: `user_message` with `message` and empty attachment arrays, or `agent_message` with `message`, `phase: final_answer`, and `memory_citation: null`.
   Keep historical tools as explicitly labeled text records, not runnable function calls. Include the original role and timestamp in the text. Grouping the import into one synthetic completed turn preserves text but not the original native turn structure; disclose this transformation.
5. Finish with `task_complete` carrying the matching turn ID. Publish atomically. Back up any importer-owned predecessor before replacement; never overwrite unrelated target history.

## Verify and index

Start a fresh app-server reader after publication. Call `thread/read` with `includeTurns: true`; parse `userMessage.content` text and `agentMessage.text` and compare every item to the expected redacted sequence. Use paginated endpoints when the installed release requires them.

Set a discoverable provenance-prefixed title through `thread/name/set`, then read it back. Save source ID, destination ID, path, expected/verified item counts, and completion status in an atomic manifest. Finally paginate `thread/list` until its cursor is empty and assert every mapped ID is present. Do not start a model request as a migration smoke test: that would transmit imported private history.

`codex migrate-rollouts` can inspect legacy-to-paginated conversion in versions that provide it. Do not assume conversion is necessary for import or apply it to unrelated sessions; inspect current help and scope any operation to exact importer-owned IDs.

## Efficient and privacy-safe implementation

Capture JSON subprocess output directly into Python before parsing; tool-output truncation can make large catalogs or transcripts invalid JSON. Print only aggregate progress and sanitized metadata. Keep scripts free of credentials and task-specific UUIDs. Regex redaction should cover common API-token prefixes, Bearer headers, and named secret fields, but preserve original snapshots locally and clearly state that heuristic redaction is not exhaustive.
