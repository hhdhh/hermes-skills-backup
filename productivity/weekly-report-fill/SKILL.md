# 周报填写（本人填写层）

> 完整描述：Use when 用户发来周报模板（本人填写层四栏）或口述本周工作要点要求成稿。把口述要点扩写成可直接粘贴的简短正式周报。

把用户口述的粗略工作要点扩写成可直接粘贴进飞书周报表单的正式文案。模板四栏固定：**本周总结 / 复盘与判断 / 需要的支持 / 下周规划**。

## 触发

- 用户发来周报模板，常附一句口述要点（顿号/逗号/「还有」分隔的长句）
- 用户说「根据飞书内容回答」「回复一下」，或直接贴新一周的工作描述

## 流程

1. **提取要点**：从口述长句拆出独立工作项。常见类型：数据清洗与客户对接、装机测试、检修与问题沉淀、比赛现场保障、软硬件/Codex 等学习项。
2. **映射四栏**：
   - 本周总结 ← 全部工作项的正式化扩写
   - 复盘与判断 ← 一条有效判断（做了什么→减少什么成本）+ 一条待改进（细化标准/流程/沉淀）
   - 需要的支持 ← 相关方确认验收标准 + 协助解决测试中发现的问题（须与工作项对应）
   - 下周规划 ← 工作项的自然延续 + 交付/闭环/学习收尾
3. **成稿**：输出与模板同名的四个加粗小节，正文紧随其后，用户直接复制粘贴。

## 风格规则（用户纠正过，必须遵守）

- **每栏 1–2 句话**。用户明确要求过「再简短一点」——首版就按简短写，不要先写长版等砍。
- 正式职场中文，动词开头（完成/推进/参与/持续/继续）；不堆第一人称。
- 复盘栏固定结构：「X 有效（能减少返工/提升效率）；后续需 Y」。
- 下周规划多事项用数字列表（1. 2. 3.），单事项一句话。
- 不编造未提及的成果、数据、人名；学习类工作（学软硬件、学 Codex）也是正式工作项，写入总结与规划。

## Pitfalls

- 用户贴模板但没给新内容时，先要一句本周工作要点，不要拿上一周的旧内容填。
- 「根据飞书内容回答」不等于去拉飞书文档——口述要点就是内容源，除非用户给了文档链接。
- 模板每周重复出现、内容每周不同：先读本周口述要点再动笔，绝不复用上周成稿。
